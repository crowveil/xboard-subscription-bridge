# 上游账户

为已保存的来源添加 HTTPS 登录页和账号密码、auth_data 或 Cookie。采用 V2Board/XBoard 兼容接口，不能仅凭网站外观判定具体版本。其他面板可通过 Services/Upstream/PanelAdapter 接口与 Adapters 注册扩展。

保存只保存本地配置。检测面板只检查公开接口；「检查并同步」才验证账户并同步最新订阅地址。密码首尾空格按原文保存，空密码表示保留既有凭据，真实换行及空字符拒绝。账户域名、邮箱或鉴权方式改变后须重新填写对应凭据。

批量保存按项目报告失败；成功项目不会在下一次重试中重复提交，失败输入留在页面。保存完再操作，未保存账户的按钮带有说明，不代表正在执行。

轮换是上游账户范围的操作，默认手动；定期和用户到期模式需明确开启并确认已实测旧节点会失效。链接改变不保证节点认证信息改变，且影响所有共享用户。一次重置写入意图后才请求上游，遇到超时只核对结果，不能再次盲目重置。

页面分别显示重置等待确认、同步地址、格式缓存刷新阶段。未确认期间暂停对应来源下发；刷新新节点后仍需有效用户更新客户端订阅。系统不能确认客户端已经更新，也不能保证既有连接立刻断开。

Cloudflare、人机验证和网站安全拦截仅检测、暂停并提示，不自动绕过。手动恢复访问后重新检测，遇到持续拦截可维持纯订阅来源方式。

Telegram 只通过 Bot API 发通知，不接管 Webhook，不接收管理指令；可与邀请插件的机器人共用。凭据、会话和轮换记录使用 XBoard APP_KEY 加密，必须保留密钥与私有数据目录。诊断导出不包含账号、密码、Cookie、Token 或原始订阅地址。
