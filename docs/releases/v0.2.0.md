# XBoard Subscription Bridge 0.2.0

本次升级基于上一公开版本 [0.1.1](https://github.com/crowveil/xboard-subscription-bridge/releases/tag/v0.1.1)。插件继续通过原有 XBoard 订阅入口分发节点，不修改 XBoard 源码，不要求用户更换订阅地址。

## 与 0.1.1 的主要区别

| 项目           | 0.1.1                            | 0.2.0                                                     |
| -------------- | -------------------------------- | --------------------------------------------------------- |
| 策略组组织     | 插件指定接收组，部分格式可补建组 | 由 XBoard 原生模板组织，随后替换为完整外部节点            |
| 上游账户       | 管理订阅链接                     | 可选关联兼容 API 账户，检查套餐、到期与用量，同步订阅地址 |
| 订阅轮换       | 无账户重置流程                   | 手动、定期、授权组用户到期触发；支持重置中断恢复          |
| Telegram       | 无上游账户通知                   | 到期与账户操作结果通知，不接收管理指令                    |
| 资源恢复       | 安装时发布控制台资源             | 启用启动时恢复缺失目录，并提供部署自检与显式修复          |
| 错误诊断       | 来源状态和脱敏事件               | 增加诊断编号、异常位置、已加载接口与进程检查              |
| 来源与账户保存 | 来源配置保存                     | 按项目显示保存结果，失败草稿保留供重试                    |
| provider 处理  | 旧来源清理功能                   | 不自动删除模板内容，必要时只提示检查并阻止相关格式输出    |
| 发布工具       | 包含早期修正与迁移入口           | 统一 `publish.sh`；不覆盖公开版本，支持离线查看升级说明   |

权限组授权、11 个生成器 / 10 个转换选项、动态控制台地址、60 分钟开放期限、Debug、加密缓存及 GitHub Actions 发布在旧版已经存在，本次继续保留。

## 订阅与缓存

- 外部节点按最终名称参与原生模板生成，复杂协议参数由对应格式的转换结果保留；插件不再维护独立的接收策略组配置。
- 替换前检查权限、名称与协议过滤，处理名称冲突及节点依赖；替换完整性校验失败时回退到干净的原生订阅，临时节点不写数据库。
- 区分明确无兼容节点、转换错误和暂时网络故障；已知的无兼容节点响应显示“已跳过”，清理对应旧节点并结束该格式的待刷新状态。
- 取消某种输出格式后清理相应待刷新项，不将取消误报为刷新成功。

## 上游账户与轮换

- 支持 V2Board / XBoard 兼容 API，账号密码、登录 Token 或 Cookie 鉴权；网站具体版本不能仅凭外观自动确定。
- 可检查账户、同步订阅地址、发送 Telegram 提醒。只需要链接的来源无需关联账户。
- 自动轮换必须显式启用，并确认上游重置确实让旧节点失效；按授权组用户到期轮换受游标与冷却时间限制，不承诺即时断连。
- 重置请求先持久化意图；超时或中断后只核对结果，不盲目重复重置。结果未确认时暂停对应来源下发，其他来源不受影响。
- Cloudflare、人机验证等安全拦截只检测、暂停和提示，不绕过验证。

## 从 0.1.1 升级

1. **备份**：数据库、插件代码目录、`storage/app/external-node-bridge`、原 `APP_KEY`，以及后台使用的订阅模板。保留旧版安装包。
2. **检查模板**：分组改由 XBoard 模板控制。将仍需要的筛选、组名和规则在模板中定义好；旧插件接收组配置不再生效。
3. **上传升级**：下载 `ExternalNodeBridge-0.2.0.zip`，在 XBoard 插件管理中上传升级。保留 `external_node_bridge` ID、`ExternalNodeBridge` 目录、来源编号及原私有存储，不要卸载后删除数据再重装。
4. **重启进程**：重启 XBoard Web / Octane 以及运行后台调度任务的常驻 PHP 进程；SCE 配置没有变化时无需因本次插件升级重建转换器。
5. **打开控制台**：在插件配置开放控制台并保存，复制自动生成的地址打开。执行部署自检，核对来源、权限组、前缀和输出格式；账户关联保持可选，轮换不要未经验证直接开启。
6. **刷新与验证**：刷新当前启用来源。分别用授权组、未授权组和过期测试用户请求订阅，核对可见节点、模板分组、各实际使用客户端及连接情况。

如果返回 `TEMPLATE_PROVIDER_REVIEW_REQUIRED`，说明旧配置记录的 provider 在当前模板仍有定义或引用。先在后台检查并移除这些遗留的外部来源引用；`rule-providers` 分流规则可保留。没有这类旧配置的用户不需要执行 provider 迁移。

容器重建后能恢复公开资源的前提是插件代码与私有数据已持久化。缺少静态资源时可运行 `php artisan external-nodes:manage repair-assets`；代码丢失应恢复或重新上传插件。不要重新生成 APP_KEY，否则无法解密原配置。

## 回退与限制

回退时使用升级前备份恢复匹配的插件、数据库与私有状态，并重启相关进程；模板如有调整也应核对。若升级后已经重置上游订阅，恢复本地备份不能撤销该重置，应向上游核对当前有效链接和凭据。

外部流量仍不计入 XBoard 自建节点统计。用户过期会阻止后续正常订阅获取，但已经下载的凭据是否失效取决于上游重置行为；重置影响共享同一上游账户的所有用户。

## 验证范围

本地回归覆盖固定 XBoard 源码的鉴权、模板分组、节点替换、权限隔离、缓存、轮换状态与控制台交互。58 项可运行 PHP 测试、18 项发布工具测试及 DOM 测试已通过。

3 项真实 SCE 集成测试因未提供可运行转换器而跳过；本地浏览器启动失败，布局测试未完成。GitHub `Tests` 工作流会运行浏览器测试，但不自动运行真实 SCE 集成测试。没有将这些未完成项目或所有客户端的实际代理握手标记为通过。

## 发布与附件

源码包含完整 README、升级说明、测试、工作流和根目录 `publish.sh`。执行 `bash publish.sh --notes` 可离线查看本文，`--check` 检查发布条件；正式执行会要求输入 `PUBLISH v0.2.0`。

脚本将源码、README 和说明一并提交。GitHub Actions 在精确提交的 Tests 成功后创建 `v0.2.0`，使用本文作为 Release 正文，上传安装 ZIP、源码 ZIP 和 SHA256SUMS。不会修改生产 XBoard，也不会覆盖 0.1.1。

- `ExternalNodeBridge-0.2.0.zip`：XBoard 安装包。
- `xboard-subscription-bridge-0.2.0-source.zip`：完整源码，解压后根目录直接提供发布入口。
- `SHA256SUMS`：上述两个 ZIP 的 SHA256 校验值。
