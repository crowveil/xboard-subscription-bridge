# XBoard 订阅桥接 0.2.0

**[打开管理控制台](/plugins/external_node_bridge/console.html)**

先在本插件「配置」中开启 **开放管理控制台（60 分钟）** 并保存，复制配置弹窗中自动生成的完整地址打开，也可点击上面的链接。需要同一域名下的 XBoard 管理员登录。未开放时，控制台只向管理员显示当前配置概要。

将外部订阅的节点与 XBoard 自建节点合并，通过用户原有的 XBoard 订阅地址分发。无需控制外部节点服务器，无需修改 XBoard 前端或内核。

## 工作方式

1. SubConverter-Extended 独立部署在 Docker 内网，插件定时请求转换结果并缓存节点。
2. 用户请求订阅时，先经过 XBoard 自身的 token、用户有效性检查。
3. 插件读取当前用户的 XBoard 权限组，只加入该组被授权使用的来源。
4. 模板格式通过临时同名节点交给 XBoard 原生分组，再替换为完整外部节点；纯节点列表直接合并。订阅请求不实时访问外部机场。

用户权限撤销会在后续订阅请求立即生效；已下载到客户端的凭据不能通过关闭控制台收回。外部流量不计入 XBoard 的真实节点统计，订阅头里的流量和到期信息仍来自 XBoard 本身。

## 安装与升级

首次安装：后台上传 `ExternalNodeBridge-<版本>.zip`，启用插件，设置转换器内网地址，开放控制台。运行环境需要 XBoard 自带的 PHP、Laravel、Symfony YAML，无需在生产插件目录执行 Composer。

使用 XBoard 插件上传升级，保留插件 ID、来源、权限组和账户配置。升级前备份私有配置和 APP_KEY，升级后重启常驻进程。旧配置曾自动清理的 provider 如果仍出现在模板中，相关格式返回 HTTP 503 并记录 `TEMPLATE_PROVIDER_REVIEW_REQUIRED`；请从后台模板移除对应定义和 use 引用。插件不再自动清理 provider。

## 容器重建与资源恢复

启用状态下，插件启动时仅检查公开资源目录是否存在；目录缺失才复制完整资源，存在则跳过。安装或升级会覆盖资源，停用或卸载清理本插件公开资源，不删除私有设置和缓存。关闭控制台只撤销管理访问。

必须持久化 XBoard 的插件代码目录、数据库、`storage/app/external-node-bridge`，并保留原 `APP_KEY`。若插件代码本身也丢失，应先恢复或重装插件；若密钥变化，恢复原密钥，不能靠重新生成密钥解密旧配置。

控制台「部署自检」检查当前 Web PHP 进程的文件与目录读写。在 XBoard 应用目录也可执行：

```bash
php artisan external-nodes:manage selfcheck
php artisan external-nodes:manage repair-assets
```

CLI 检查的是执行命令的用户；用 root 执行成功不代表 Web PHP 用户有权限。不要用 `chmod 777` 代替正确的持久化和目录属主配置。目录存在但资源不完整时，主动使用 `repair-assets` 修复。资源发布失败会保留可重试状态，并输出 `ASSET_LIFECYCLE_FAILED` 到 PHP 错误日志及可用的脱敏诊断日志。

## 控制台

- 「保存」只保存配置，不关闭页面，也不强制刷新节点。
- 「关闭控制台」撤销所有标签页的管理接口访问；有未保存内容时可选择保存并关闭、放弃并关闭、继续编辑。
- 默认开放 60 分钟，可在到期前续期；到期后须回 XBoard 插件配置重新开放。
- 关闭不影响后台刷新、已有缓存或用户订阅。已开始的管理操作先结束，关闭成功后旧请求不能继续写入。
- 静态 HTML 文件仍可被打开；敏感配置、管理操作和诊断导出受后端访问开关与管理员鉴权共同保护。

原生 XBoard 插件表单仅支持配置字段，目前不支持插件自定义动态操作按钮。插件通过后端配置服务扩展，在开关说明中动态展示完整控制台地址，用户复制打开；不注入脚本、不修改管理端打包文件。地址基于当前后台请求（包括 XBoard 信任代理解析后的协议、域名与端口），不使用可能指向其他前台或 CDN 的域名。启用插件后生效；禁用时保留静态说明。换域名后重新打开配置即可，链接本身不授予权限。

## 来源字段

| 字段     | 含义                                                            |
| -------- | --------------------------------------------------------------- |
| 来源名称 | 管理员可随时修改的名称，建议使用机场名称                        |
| 订阅地址 | 完整 URL，管理员控制台直接显示和编辑                            |
| 权限组   | 复选框多选，可全选、清空；未选择时不刷新、不分发                |
| 刷新间隔 | 以分钟输入，至少 5 分钟，默认 60 分钟                           |
| 启用     | 控制此来源是否参与刷新和分发                                    |
| 节点前缀 | 高级项；新来源默认 `[来源名称]`，已保存前缀不随改名变化，可留空 |
| 输出格式 | 高级项；新来源默认全选，可按客户端需求选择                      |

内部来源 ID 自动生成；修改名称不会改变 ID。删除再新增属于新来源。前缀一旦保存独立于来源名称，避免改名时意外改变客户端节点名称。URI 格式也会添加已保存的前缀，凭据保持不变。

订阅地址在授权界面明文显示；磁盘私有配置和缓存使用 XBoard `APP_KEY` 加密。请同时备份数据库、`storage/app/external-node-bridge` 和原 `APP_KEY`。

## 上游账户管理

「上游账户」页为已保存的来源关联账户，填写登录页地址和账号密码或登录 Token，保存后检测面板、检查并同步。可设置检查间隔和 Telegram 到期提醒，关闭控制台后定时任务继续运行。

轮换默认只手动；需要自动轮换时，先确认重置后旧节点确实失效，再启用定期或用户到期模式。一次轮换影响整个上游账户，所有共享用户均需更新订阅。链接变化不保证节点凭据变化。检测到 Cloudflare 等安全阻拦只暂停并提示，不尝试通过验证。

重置中断后使用「重新检测并恢复」，插件只查询结果，不重复重置。待确认期间暂停此来源下发，其它来源正常。账户密码、登录 Token、Cookie 和机器人 Token 加密保存，不回显，不进入诊断导出。

取消输出格式后，其待刷新项会在保存来源配置时清理；后台调度也会核对已有状态。取消格式不视为刷新成功，不会为此发送“全部刷新完成”的通知。

详细说明见完整源码中的 `docs/upstream-accounts.md`。

## 转换格式

| XBoard 生成器 / 入口                  | SCE target       | 合并方式                             |
| ------------------------------------- | ---------------- | ------------------------------------ |
| Clash、Clash Meta                     | `clash`          | 原生 YAML 模板分组后替换 proxies     |
| Stash                                 | `stash`          | 原生 YAML 模板分组后替换 proxies     |
| Sing-box                              | `singbox`        | JSON outbounds 与 selector / urltest |
| Shadowrocket                          | `shadowrocket`   | Base64 URI 列表                      |
| Surge                                 | `surge`, `ver=5` | 原生 INI 模板分组后替换 Proxy 段     |
| Surfboard                             | `surfboard`      | 原生 INI 模板分组后替换 Proxy 段     |
| Loon                                  | `loon`           | 原生节点文本列表                     |
| Quantumult X                          | `quanx`          | 原生 Base64 节点文本列表             |
| General / v2rayN / v2rayNG 等通用入口 | `mixed`          | Base64 URI 列表                      |
| Shadowsocks                           | `sssub`          | SIP008 servers                       |

覆盖 XBoard 当前 11 个生成器，控制台为 10 个转换选项。Clash 暂按 Mihomo 格式转换，旧 Clash 内核可能不支持扩展协议。XBoard 没有原生入口的其他 SCE targets 不单独新增分发 API。

SCE 负责按目标格式过滤它不支持的协议；这不等同于检测每台客户端的具体版本。插件不会将不同客户端的结果混用，也不会尝试自行修复不完整协议字段。请使用支持相应协议的客户端版本。通用入口统一使用 mixed，不承诺所有别名客户端支持 mixed 的全部协议。

## 模板与节点分组

策略组、筛选条件、测速参数、DNS 和规则在 XBoard 后台订阅模板中维护，插件没有独立组名配置。Clash / Clash Meta / Stash、Sing-box、Surge / Surfboard 使用临时同名节点参与原生模板生成，再用对应客户端的完整外部节点替换节点定义；只读模板，不写入 XBoard 源文件或节点数据库。

来源权限和请求的协议、名称过滤先作用于真实外部节点，随后才生成临时节点。临时节点不赋予真实外部协议任何兼容保证；输出支持仍由 SCE 的目标能力决定。Loon、Quantumult X、通用 URI 和 SIP008 列表直接合并。

外部名称先去重，关联节点引用同步改名；缺失依赖和循环引用会跳过。模板匹配使用带来源前缀的最终名称。替换缺失、重复或残留临时标记时，返回干净的原生订阅并记录诊断。其他订阅修改插件必须单独验证兼容性。

插件只控制自己添加的节点，不控制原模板中独立配置的来源。不要把需按权限隔离的订阅凭据另外写入公共模板。

## 转换器与缓存

部署示例使用独立的 `aethersailor/subconverter-extended:v1.9.6`，与 XBoard 共用 Docker 网络，端口不向公网映射。源码包附最小部署示例和真实转换器测试入口；本次本地回归未运行真实转换器进程，验收范围见完整源码的发布说明。

转换器需要保留镜像自带的 `base/stash.yaml`；Stash 即使 `list=true` 仍读取基础模板。插件显式请求节点列表并禁用默认远程规则预设，不部署 Sub-Store。

「检测连接与版本」由 XBoard 服务端访问配置地址的 `/version`，显示实际服务版本和检测时间；定时任务也会检查。无法识别版本时显示失败状态，不清空缓存，不使用 GitHub 最新版本冒充本机版本。

转换器版本变化后会安排重新转换；「立即刷新全部」可手动重建当前有效来源缓存。

上游 User-Agent 默认 `clash.meta`，请求机场返回原生 Mihomo YAML，避免通用 URI 丢失 XHTTP 的下载地址、路径、SNI 等字段。修改转换器地址或 UA 后需要保存并刷新。缓存不会跨订阅 URL、目标格式或 UA 复用。

“转换请求超时”控制插件等待转换器的时间。“缓存最大有效时长”从最后成功刷新起算，与刷新间隔和用户套餐到期无关。网络错误、5xx、429 时可继续使用有效期内的旧缓存，默认 24 小时。确定的拒绝或无兼容节点会停止下发相应来源格式；超过年龄上限不再分发。明确无兼容节点显示为“已跳过”，结束轮换待刷新状态，后续定时刷新仍会检查新增节点。HTTP 400 只有响应与 SCE 已知的无兼容节点错误完全一致时才归入该状态。

## Debug 与排查

升级后请重启 XBoard 容器或 PHP / Octane 常驻服务，再刷新控制台。出现 `PLUGIN_RESTART_REQUIRED` 表示已加载的组件缺少新版接口；重启后仍异常时，应检查插件文件是否完整更新。控制台版本号来自 manifest，不能证明所有 PHP 类都已重新加载。管理接口检查已加载组件的必要接口；诊断中的 `runtime` 包含接口检查结果和进程编号。这项检查可以识别缺失接口，不能替代升级后的进程重启。

“管理控制台加载失败”与关闭状态分别显示。异常页面提供诊断编号、文件名和行号，可用编号与下述日志中的 `trace` 对照；异常原文和凭据不会输出。

控制台「运行与调试」可开启 60 分钟 Debug、查看每个来源和格式的节点数量、刷新时间、错误状态，以及导出诊断 JSON。日志不含订阅 URL、节点地址、密码、UUID、原始响应或 token。

日志位于 `storage/app/external-node-bridge/diagnostics.jsonl`，单文件约 1 MiB 后轮转，最多保留当前和上一份。导出最近 3 天内最多 1000 条事件。XHTTP 的检查只记录字段数量，不记录字段内容。

服务器命令行（已进入 XBoard 容器和应用目录）：

```bash
php artisan external-nodes:manage status
php artisan external-nodes:manage refresh --force
php artisan external-nodes:manage diagnose
```

CLI 使用服务器本地权限，不受网页控制台开关影响。来源刷新依赖 XBoard 的 Laravel scheduler，必须保持调度器运行。SCE 日志由其自身配置管理，建议保持 warn 等级。

## 兼容范围与开发

集成验证基于 cedar2025/Xboard `4f48e61a2cbc6db5338872b6bdb45ef954ec1256`。使用 `client.subscribe.servers` 优先级 10000，在原生鉴权之后调用实际生成器，然后拦截合并后的响应。更高优先级数字的其他同类订阅插件可能受到拦截顺序影响，不建议同时启用第二个外部节点合并插件。

来源配置独立存储，原生后台保存其两个字段不会清除来源。私有文件不可解密时会停止外部合并并记录错误，不尝试猜测或覆盖配置。

发布版本以 `config.json` 为准。测试使用固定的 XBoard 生成器与合成凭据，覆盖鉴权、缓存、字段保留、模板分组和失败回退；真实转换器测试需要另行提供 SCE，测试不连接真实代理节点。
